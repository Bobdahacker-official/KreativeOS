# ASRock A520M-HVS boot profile

Read-only Windows hardware inventory identified an ASRock A520M-HVS with firmware P3.50, an AMD Ryzen 5 4500 with 12 logical CPUs, 32 GiB of RAM, AMD xHCI controllers `1022:1639` and `1022:43ec`, an AHCI controller `1022:43eb`, and an ADATA Legend 800 NVMe drive. Windows reported UEFI Secure Boot disabled at the time of inspection. The profile uses xHCI and UEFI GOP. The QEMU launcher allocates 1 GiB of guest RAM. [ASRock motherboard specifications](https://www.asrock.com/mb/AMD/A520M-HVS/index.asp)

The combined image boots from a dedicated USB device and stores data in its second partition. Discovery reads GPT, primary MBR partitions or whole-device exFAT. A normal exFAT volume mounts read-only until first-boot confirmation or sign-in to an existing account on that volume. Writes stay inside the selected data volume. [UEFI GPT specification](https://uefi.org/specs/UEFI/2.11/05_GUID_Partition_Table_Format.html)

The motherboard has a Realtek RTL8111H Ethernet adapter. KreativeOS does not have a native RTL8111H driver. The QEMU profile presents RTL8139 to the guest and uses the host's network connection. Physical display uses UEFI GOP; there is no accelerated NVIDIA driver. The USB profile was designed for the detected controller class. It has not been booted on this physical motherboard.

## USB and filesystem design

The driver claims PCI xHCI controllers after firmware boot, negotiates device slots and endpoint contexts, and polls command, transfer and event rings. Boot protocol HID keyboards and mice and bulk-only SCSI mass storage work on directly connected root ports. Connect them before boot. The storage path is BOT, LUN 0, with 512-byte and 4 KiB logical sectors. USB hubs, UASP and arbitrary HID report descriptors require additional drivers. [Intel xHCI specification](https://cdrdv2-public.intel.com/625472/625472_xHCI_Rev1_2b.pdf) · [USB HID specification](https://www.usb.org/sites/default/files/hid1_11.pdf) · [USB Bulk-Only Transport specification](https://www.usb.org/sites/default/files/usbmassbulk_10.pdf)

The data volume uses exFAT 1.00 for portable files. The kernel reads on-disk geometry, follows FAT chains, verifies boot and directory entry checksums, and flushes changes before clearing the dirty flag. KreativeOS manages small root files on a clean single-FAT volume. Use host tools to recover a dirty volume. The firmware partition uses FAT for UEFI compatibility. [Microsoft exFAT specification](https://learn.microsoft.com/en-us/windows/win32/fileio/exfat-specification) · [UEFI media access](https://uefi.org/specs/UEFI/2.10/13_Protocols_Media_Access.html)
